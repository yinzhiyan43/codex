## 实际实现

工作台设置中的“主题 / 外观”提供浅色、深色、跟随系统。统一 `theme.css` 定义语义颜色，主窗与只读副窗共享；主窗、聊天气泡、侧栏、搜索、设置、会话/账户菜单、审批/状态提示、输入、原生选择框、禁用态、焦点和选中态均使用变量。明暗配色保留相同布局与行为；关键文字组合至少4.5:1，焦点与控件边框至少3:1，装饰性分隔线保持适当层次。

偏好只存在工作台独立的 `ui-preferences.json`。v2增加 theme；旧v1文件读取时在内存迁移，保留此前深色外观、侧栏宽度、密度、字号与折叠分组，读取不改原文件。新安装默认跟随系统；下一次明确修改偏好才原子写v2。非法更新值直接拒绝；v2中非法主题值回退system，其他有效偏好保留，原文件不自动覆盖。损坏、未来版本、不安全链接和超大文件仍保留并禁用偏好写入，显示system外观回退及重读入口；修复后不重启即可重读并应用。

主进程在创建窗口前读取偏好，BrowserWindow初始背景与有效主题一致。每个preload通过只读、同步、有界的本地引导取得 mode/resolved/revision；主进程核对具体窗口、主frame、精确页面URL并沿用IPC预算。自托管阻塞 `theme.js` 在CSS前设主题属性，避免先绘制固定深色再等待异步偏好。preload先注册广播监听，再取快照；revision阻止旧快照覆盖较新广播。主窗与副窗只暴露主题初值/订阅，副窗没有偏好写入口。

模式修改成功保存后，主进程只广播主题并更新自己拥有窗口的背景。已有副窗同步、新窗使用最新初值；不替换DesktopView、重建会话或核心。跟随系统只读 `nativeTheme.shouldUseDarkColors` 并监听 `updated`，不设置 `nativeTheme.themeSource`、系统外观或共享Codex配置；显式浅/深色忽略系统变化。系统变化只重算有效主题，不写偏好文件。关闭主窗移除系统监听与主题IPC，再销毁副窗及原受控核心。

打开设置仍先保存防抖草稿；保存主题期间短暂禁用控件后恢复原控件焦点。切主题不会修改聊天路由、模型、推理、速度、待发送内容或生成状态。主题专项验证一次合成流式回合跨主题变化继续完成，只发一次合成turn/start、无interrupt，真实模型请求为0。已有搜索及会话管理保持原界限；本轮未扩展可编辑多窗、分享、删除或搜索能力。
