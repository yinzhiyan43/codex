## 边界与新增能力

核心仍为 `rust-v0.162.1` / `092d3acd6bec3e3a14bdc7e7a2810ab628ab759d`，UI 参考仍为 `26.1007.30912` / build `20156`。只修改独立 workbench 与阶段文档，没有修改官方核心、版本、锁文件或已选 Logo；没有 push。

在固定提交的现有生成协议中新增 turns/items list 的参数及响应4份快照；总计19份 schema，SHA及内容与固定 Git 提交校验。adapter、host 和受限 IPC 接通 `thread/turns/list`、`thread/items/list`；请求有字段白名单、页长1–100、4096字符标识/游标限制，响应校验页长和指定 turn 归属。类型化 item anchor 使用官方 `{type: "item", itemId}` 结构并要求 turnId。实验能力仍关闭。

首次读线程只取 metadata，再取轮次/项目页。UI 只送当前 threadId，不拥有任意游标。每个线程用独立历史窗口保存服务器页顺序；以 thread/turn/item 组合 ID 定位和去重，不以字典序或时间戳重排。降序页转换为正序显示；旧页前插，重叠项更新且保留已有位置与 DOM 节点。已完成正文不会被迟到的部分正文覆盖。

轮次和项目页作为一组原子提交；错误、取消、路由切换或跨连接迟到结果不更新缓存/游标。请求 token 归属保护快速切走返回与取消立即重试。重连重新读取事实，旧缓存逐项保持 stale，直到重读；两类分页均完成时清除本代未出现的旧记录。分页不会自动重复 turn、审批或文件动作。页响应没有 threadId，关联依赖请求 ID；不能从响应本身证明任意真实服务返回的线程语义。

历史每线程最多128轮次、512项目和2 MiB，最多64页游标记录；最多16个尚未结束的读批次。循环游标/过大缓存给出可重试错误并保留原状态。这是有界显示缓存，不是完整历史数据库。

审批卡由主进程维护真实 handle，只向 renderer 暴露不透明 key 和受限展示字段；最多64卡。当前支持命令/文件请求的同意一次、拒绝和取消。待决定 → 已发送待解决 → 服务端已解决；没有本地答复而被服务端解决的请求显示“已失效”，不推断 TTL 或撤销原因。断线卡显示结果待核对且不可答复。重复点击、旧 epoch 和跨路由答复不再发送新决定；答复审批不宣称任务执行成功。
