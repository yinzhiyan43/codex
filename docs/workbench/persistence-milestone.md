## 保存与恢复

`npm run desktop:chat` 启动当前新工作台，沿用官方 CLI 托管的 ChatGPT 登录与服务端 GPT 目录。首次确认发送通过 `thread/start(ephemeral:false)` 创建持久线程。官方核心拥有完整会话存档；工作台保存自己的标题、草稿、模型选择、置顶、未读、归档结果待核实标记和最后选择 ID。草稿未发送不会创建官方线程。

Mac 的应用数据目录为 `~/Library/Application Support/Codex Workbench/`：

- `sessions.json`：版本化的工作台元数据与未发送草稿，原子写入，权限 0600；不复制持久会话正文。
- `core/state/`：官方核心通过 `sqlite_home` 使用的持久投影。
- `core/chat-cwd/`：稳定的纯文本聊天 cwd；`core/log/` 为核心日志目录。
- 完整官方 rollout 仍由核心写入其 `CODEX_HOME`，默认 `~/.codex/sessions/`，归档由核心处理；它们并不全部位于 App 数据目录内。

退出保留持久目录。原官方配置不改写，凭证由官方核心原位使用、不复制。普通工作台使用单实例锁，避免同时写自己的会话索引。

重启只执行握手、账户/配置/目录检查，以及选定线程元数据和完整轮次的只读分页；不自动 `thread/resume`、`turn/start` 或重发未知请求。“继续聊”也只读取记录；下一次明确确认发送才恢复同一个线程 ID，然后新增一轮。完整轮次与实时消息以组合 ID 合并、保持顺序和去重。

旧临时线程只保留实际观察缓存，标为过期/未知；关闭后从未保存的文字不能恢复。发送会创建新的持久线程，不假称继承旧临时上下文。缺失存档、创建失败和仍在进行的历史轮次不会被伪造为恢复成功。

存储损坏、新版本或写失败不覆盖旧文件，禁用发送；明确重连先验证存储可写。断开立即失效当前发送/恢复意图并先停止受控子进程，再等待元数据保存；断开中禁止重连。慢写入不能让旧发送迟到、旧连接复活或旧断开停止新连接，旧配置失败也不能干扰新连接。执行中手动断开保持结果未知提示。

归档结果未知的线程持续禁用续聊，目录读取不能解除锁；明确成功的恢复归档 ACK 才清除标记。切到未知归档目标不会将当前正文或草稿错置到另一 ID。
