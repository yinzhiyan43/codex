# M2.d 会话分叉、发现与归属管理

日期：2026-10-15。上一交付 `7645df6281712835940f7e6364fc03fca8a794bd`，分支 `workbench/desktop-stable-0.162.1`。核心仍为 `rust-v0.162.1` / `092d3acd6bec3e3a14bdc7e7a2810ab628ab759d`，界面参考仍为 `26.1007.30912` / build `20156`。本轮只增加可验收的会话管理能力，未完成全部工作台；原 92 个目标保留。

## 当前可用流程

在 `npm run desktop:chat` 的已保存会话右键菜单：

- “分叉”先显示完整会话分叉确认；取消确认不发送 RPC。确认后调用官方 `thread/fork`，持久登记返回的新 ID 与 `forkedFromId`，读取完整轮次后打开子会话，不自动调用模型。源正文与未发送草稿保留，子会话草稿独立。
- 分叉继承工作台本地项目标签。官方分区以返回的官方元数据为准，不自行假定继承。主侧栏及历史中的“已登记分叉 · 本地索引”可再次打开普通服务器列表暂不显示的子 ID；重启亦可恢复。
- “项目”打开明确标注的工作台本地标签对话框。输入标签即可归组，留空清除。它不创建官方项目、不改 cwd、不移动文件；没有调用实验项目接口。
- “分区”读取官方列表，可显式创建官方分区，再移动会话到所选 ID；选择“不属于任何分区”可移出。分区由官方核心保存，工作台索引仅保留归属显示。允许同名分区，选择新建结果时按官方返回 ID 绑定。
- 既有重命名、置顶、未读、归档/恢复、正文分页与草稿语义保留；重启只读恢复，下一次确认发送才 `thread/resume` 并继续同一线程。

原参考图仅展示 11 个顶层入口，没有提供子菜单内容。本轮为这些入口接入自己的确认/归属对话框，不声称复刻未知子菜单或完成像素级对照。复制子菜单、新窗口仍禁用；分享、永久删除仍只是非执行说明，没有产生链接或删除请求。

## 分叉为什么未出现在普通列表

固定源码中的两条过滤均排除空预览：

- [SQLite 列表过滤](../../codex-rs/state/src/runtime/threads.rs) 在普通未归档查询中要求 preview 非空；指定 section 过滤时例外。
- [rollout 文件列表](../../codex-rs/rollout/src/list.rs) 只接纳已有 preview 的存档；引用祖先历史并不等于新分叉有自己的用户消息事件。

新 paginated 分叉可有完整继承历史，却没有自己的用户消息，返回 preview 为空。`threadSource` 是独立分类，改它不能解决该过滤。本轮没有改核心或制造用户消息来填 preview。

隔离原生实证：新分叉空 preview；重启后按返回 ID 读到三轮正文并可恢复相同 ID，普通列表仍不含它；移入官方分区后，指定 section 的列表能发现该 ID，分区与归属跨进程保留；移出后普通列表仍过滤。源完整正文及原 rollout 字节均未变化。工作台登记的是官方 ACK 的真实 ID，不是伪造正文或服务端目录。

| 能力 | 固定 0.162.1 事实 | 本轮处理 |

| 分区重命名/删除、顺序/外观 | 已有标准协议，但本轮未接入 | 保留能力记录，后续分阶段验收 |

六份分区 Params/Response schema 从固定上游复制，当前共 49 份；host 和 IPC 仍逐方法/逐字段允许。分叉响应必须是不同于源的合法 ID，`forkedFromId` 必须匹配源，校验先于实时投影替换。不能以另一个线程覆盖源。

## 并发、取消和失败

发送、恢复、分页或会话管理忙时，新的创建/移动请求被拒绝。重复分叉确认只创建一个子会话。分叉开始前保存当前草稿并验证有效配置及源线程非活动/持久，并依据本地已知归档状态和当前历史视图拒绝归档来源（Thread 元数据本身没有归档字段）；管理索引先为源和子记录预留容量。

分叉请求前持久保存“结果待核实”标记。ACK 后即使已取消自动打开，也登记真实子 ID。取消在路由提交前有效；已发出的 RPC 没有上游取消保证，按钮明确称“取消自动打开”。一旦路由开始提交便结束该取消窗口。断开会停止受控进程，不自动重试或打开迟到结果。

核心创建和本地文件不构成跨进程事务。若创建响应丢失，不能猜测未知子 ID，也不能宣称已撤销核心动作；源保留未知标记，阻止自动/重复分叉，待诊断或人工核对。若已 ACK 而本地写失败，返回 ID 留在内存，发送禁用；成功重连写入后可保留该登记。崩溃同时丢失尚未落盘 ACK 时，仍以此前未知标记防重复，不承诺重建未知 ID。

元数据修改与保存串行，失败的本地归属事务回滚，不覆盖后来的草稿。官方分区移动若响应或后续保存未确认，不能声称远端回滚；显示待核对，重新打开/重连读取官方元数据。分区创建结果未知时，同一核心代次内禁止重复创建，重连停止旧进程后再刷新。

对话框固定初始目标 ID；异步右键切换不改变提交目标。同名分区按返回 ID 选中。新增归属字段写前和加载时均校验，既有官方分区名称中的控制字符规范化后用于本地显示，不能污染下次启动的索引。

## 保存位置与预算

沿用 M2.c 的 `~/Library/Application Support/Codex Workbench/sessions.json`，添加可选本地项目、官方分区镜像、分叉父 ID 及未知状态字段；既有 version 1 文件可直接读取并保留旧字段。原子私有写入策略不变；未实现将新增元数据降级回旧代码时的完整保留保证。

官方完整历史仍由 `CODEX_HOME` 保存，投影仍为工作台 `core/state`。本地标签不改变 `core/chat-cwd`，不改原官方配置，不复制登录凭证。

服务器历史目录仍限 200 行/16 页；已登记分叉另占有界索引区，受 512 条工作台总记录限制，历史侧栏去重后最多 200 + 512 行，不静默挤掉服务器记录。主工作台分组使用有界 512 条记录。正文缓存仍为 8 个线程、每缓存 256 轮/64 页/2MiB、4 个读取请求；单帧 1MiB 限制未变化。官方分区最多加载 4 页/64 项，超限或游标循环保留原列表并报告错误。真实大历史性能尚未验收。
