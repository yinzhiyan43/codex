## 启动与使用

```sh
cd ~/study/codex/workbench
npm run desktop:chat
```

使用既有官方CLI的ChatGPT登录。侧栏点击“浏览历史会话”，查看未归档的持久会话；“更多会话”由 thread/list 的服务端 nextCursor 推进。选择会话后，“加载更早轮次”由 thread/turns/list 的服务端 nextCursor 推进；“刷新记录”重新读取元数据和首个完整轮次页。“刷新列表”重读列表首个页，已选中的较早记录保留已验证标题与显式刷新入口。“返回当前聊天”保留原聊天、模型和草稿。历史页禁用输入、发送与模型切换，不恢复执行或启动模型。

当前新聊天仍为临时会话。固定核心拒绝临时会话正文重读和轮次列表；“核对当前会话元数据”改用 thread/read(includeTurns:false)，只核对元数据，正文保留此前观察到的缓存。界面明确提示这一限制。不会为了历史访问自动改成持久会话，也不把缓存称为重新读出的完整正文。重连沿用现有行为：重置当前临时线程、保留观察缓存与草稿；下一次人工发送创建新临时会话，不自动重放。

## 实际协议证据与实现

先核对固定源码和schema，再运行一次禁网、全新 HOME/CODEX_HOME/cwd 的原生合成探测。隔离存档来自官方测试使用的legacy rollout结构，含3个合成会话、每个3轮；未接触用户认证或真实历史。

| 接口 | 实际隔离结果 | 产品用途 |
| --- | --- | --- |
| thread/list，limit=1 | 首个/下一页为不同存档，nextCursor有效 | 未归档列表，生产每页请求20条 |
| 持久 thread/read(includeTurns:true) | 读出3轮完整记录 | 能力确认；产品不用全量正文读取 |
| 持久 thread/turns/list(itemsView:full)，limit=1 | 首轮 turn-3、下一页 turn-2，含完整用户/助手item | 正文使用真实服务端分页，每页请求20轮 |
| thread/resume | 在隔离数据中恢复3轮元数据/正文，未发送turn/start | 仅探测支持程度；产品浏览不调用resume |
| 临时 thread/read(includeTurns:false) | 元数据成功 | 当前临时会话核对 |
| 临时 includeTurns:true / turns/list | 均返回 -32600 | 明确不可重读正文；保留缓存 |
| thread/items/list | 既有实际证据为不支持；本轮未再请求 | 官方浏览与诊断不调用；仅保留旧合成演示适配器 |

原生二进制 `0.162.1`、darwin-arm64、SHA256 `74c6a6d263f40d65f99c27a815275f5b4ed0bcc2baecc396b4cf3255498bdfc0`。探测结果passed，模型请求0，进程exitCode=0，无signal。可显式复现 `npm run history:core:check -- --result /absolute/result.json`；此命令仅创建/删除自己的隔离合成数据、运行固定核心，日常 check 和 UI smoke 均不运行核心。后续只检查了探测脚本语法与设置失败清理，没有重复原生探测。

Typed API新增 thread/list 的两份固定schema，合计33份。历史元数据走仍验证schema和threadId的专用 readThreadMetadata 路径，固定 includeTurns:false，不进入实时投影，避免浏览第129个历史线程填满投影。正文只由独立 FullTurnsWindow 保存；不把全量正文在前端切片冒充服务端分页。

降序服务端页反向显示为时间顺序，按thread/turn/item复合ID去重；不按相同正文去重，也不依赖可能相同的时间戳或ID字典序。刷新首个成功页原子替换旧轮次；读失败保留缓存。旧意图、切换后的页和旧连接代的回复失效；取消仅取消显示提交，不声称已撤销核心读取。断线缓存标为stale，重连不自动读取历史、resume或重发turn。返回当前聊天后，在未完成的历史请求结束前禁止新发送，防止迟到读取影响实时执行。

IPC只接收列出的动作及已验证会话ID，不接收cursor、路径或任意RPC；缓存窗口最多8个，同时请求最多4个。renderer只接收标题、ID、文字与状态，不接收原始历史路径/cwd/配置；测试包含路径泄漏陷阱。历史的inProgress只显示为未完成历史状态，不显示为当前运行或允许停止历史执行。

## 容量与未实现边界

列表最多200会话/16页，单个历史窗口最多256轮/64页/2MiB规范化展示缓存（序列化）。达到上限保留已提交缓存、明确提示本地展示上限、关闭继续加载；显式刷新可重新开始。最多8个窗口，因此正文缓存理论总量最多16MiB，连同有界元数据、IPC/投影仍有暂存和序列化开销；不称作整个进程的内存峰值预算。

固定核心源码 thread_processor.rs:3120–3128 明确每次legacy turns请求会重放整个rollout以重建轮次，再生成页。服务端分页减少传输量，但不能证明核心CPU/内存随页大小有界。JSONL单帧上限1MiB；一个极大的完整轮次在到达展示上限之前就可能超限，使host失败。界面保留缓存、提示可能超限并要求显式重连；不会回退items接口、静默截断正文或修改核心。此次3轮存档探测不是长真实历史性能验收。

仅浏览未归档持久记录，只展开用户/助手纯文本。附件、工具item、归档列表、在历史上继续执行/分叉、历史搜索、真实大历史滚动/性能仍待实现或验收。thread/resume的实际支持不能视为这些产品功能已完成；对非legacy存储没有本轮成功真实数据证据，失败保持明确状态。没有读取/上传用户真实历史、截图或配置。
