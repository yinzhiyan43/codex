## 本轮范围

原有架构由单个主控制器拥有草稿、发送确认和持久化状态。本轮先报告最小范围，再启用菜单“在新窗口中打开”：打开选定持久会话的只读副窗口。副窗口支持保存正文分页、刷新和取消读取；没有输入框或发送、模型选择、重命名、归档、分享、删除等写入口。

主窗口独占草稿与发送权，因而副窗口不能静默覆盖草稿，也不能绕过确认或产生第二个发送者。主、副窗口可查看相同会话；再次打开相同 ID 聚焦已有副窗口，最多四个不同会话副窗口。开窗在主窗口可管理状态下接受已知持久 ID，不接受路径、任意 URL 或临时会话。开窗前原主窗口草稿照常保存；副窗口读取不改变主窗口路由、分页或正文。

这不是完整可编辑多窗口。副窗口是工作台自有的只读文字界面，不声称复刻未知参考窗口内容；可编辑窗口的草稿版本冲突、发送所有权转移和窗口拓扑恢复仍待后续设计与验收。

## 状态、读取与 IPC

- 主窗口继续使用原有控制器、SessionStore 和发送确认逻辑。副窗口不持有 SessionStore，snapshot 不包含主窗口草稿、待发送内容、账户或其他会话数据。
- 每个副窗口固定一个来源 ID，独立 FullTurnsWindow、游标、取消 intent 与展示状态。仅调用标准 metadata read 和完整轮次分页，不 start/resume/turn，不展开附件/工具，也不制造 UI 等待占位正文。
- 所有副窗口合计最多四个读取 lease，包含已关闭但底层请求尚未返回的窗口。取消/关闭只使结果失效，不取消共享核心；底层 Promise settle 后才释放 lease。主窗口保留独立的既有预算。单副窗口一次读取，沿用 256 轮/64 页/2MiB 展示与 1MiB 协议帧上限。
- 副窗口使用独立 preview HTML、preload、事件与 IPC 频道。主进程检查确切 webContents、主 frame 和精确 `workbench://app/preview.html` URL，再只允许刷新、同 ID 更早轮次、取消读取、清除错误。发送、草稿、连接控制、换来源和开其他窗口均被拒绝。主窗口频道仍只接受主窗口与 index URL。
- 所有窗口关闭 Node 集成、启用 contextIsolation/sandbox；网络、权限、任意导航、webview 和 window.open 继续被拒绝。新窗口仅通过受限主进程命令创建。

主窗口已确认的名称与归档/恢复状态会传给对应副窗口，传递字段只含 ID/名称/归档标志。副窗口读取中的旧元数据不能覆盖较新的主窗口确认名称。外部客户端改名可显式刷新读取；外部归档因 metadata 没有归档字段，本轮不承诺自动探测，显示的是主窗口已知状态。

主窗口断开或代次改变时，副窗口保留陈旧缓存并禁用读取；主窗口重连就绪后广播状态，使刷新按钮重新可用。副窗口不自动重读、不重连、不发送模型任务，用户显式刷新后才清 stale。保存分页没有服务器快照，官方写接口仍没有 CAS，外部并发限制沿用 M2.f。

## 关闭与重启

关闭副窗口会退订监听、失效在途响应并销毁该窗口；不会停核心、切换主会话或写草稿。已关闭窗口的迟到读取不会发布，也不会更新另一个副窗口。

关闭主窗口先禁止开新副窗口、退订同步并销毁全部副窗口，再由唯一主控制器保存草稿和停止受控核心。重启沿用主窗口的会话/草稿恢复规则，不自动重开副窗口，不自动发送或恢复模型执行。菜单可显式重新打开同一保存 ID；会话历史仍由官方核心保存，副窗口不复制或删改它。
