## 选定增量及范围

按继续指令先核对工作区，基线干净且本地比远端多一个提交。现有官方完整轮次读取接口可支持文字复制，菜单也有复制入口；新窗口需要额外处理多窗口草稿与生命周期。本轮先报告并选择“复制已保存文字”，没有臆造参考应用未知复制子菜单，也未新增窗口。

菜单中的“复制已保存文字”显示明确确认说明，再完整读取所选持久会话。内容按服务器轮次/条目顺序输出用户和助手文字，保留重复文本；不复制未发送草稿，不展开附件/工具，不复制 UI 合成的等待/失败占位文案。归档持久记录可只读复制；临时会话不可复制。

读取使用独立窗口缓存，现有消息、分页位置、源记录、模型选择与草稿均不受影响。只有服务器游标明确结束、所有轮次终态、同 intent/generation 且第二遍完整读取指纹相同，并且最终元数据仍可只读时，才一次调用主进程注入的剪贴板写入。空文字、读取不支持、错误、变化、超出 256 轮/64 页/2MiB 或帧限制均不复制残片。取消和断线不写；重启不重放复制。

renderer 只发送合法已知 ID，不能提交任意剪贴板文字、路径或原始 RPC。生产主进程使用 Electron `clipboard.writeText`；测试注入内存写入器，不读写真实系统剪贴板。若写入器抛错，状态明确为“写入未确认”，不假称未发生写入或自动重试。复制结果和取消控件位于可见主布局内，有状态文本与 900px 视口检查。

## 外部编辑可验证边界

官方固定协议的 `threadSection/update`、`thread/name/set` 和 `thread/section/move` 没有 expected revision/name/order 或 CAS 参数；SQLite 事务只序列化单次移动。分区、完整轮次分页也不提供跨页快照，秒级 `updatedAt` 不能用作可靠版本条件。

工作台现在在写前重新读取并比较已观察到的分区名称、目标线程归属和完整目的区 ID 顺序；会话名称也与已观察显示值核对。发现外部变化或无法完成核对时，停止旧操作，不发送替换写入，要求刷新后重新选择。分区对话框按固定目标 ID 读取当前官方归属，不再用未核对的本地默认值代替。

移动后重读成员和顺序，核对目标位置以及其他成员的相对顺序，再单事务导入本地镜像；重命名 ACK 后也重新读名称。不批量覆盖官方分区列表或其他线程状态，不自动重试或逆向撤销另一客户端的动作。后置核验失败时不能声称远端回滚。

无法保证的窗口仍存在：最后一次核验之后、请求落盘之前，另一客户端仍可修改同一目标；该协议不能原子拒绝这一竞争。跨页有遗漏而无重复的外部重排也可能无法检测。两遍复制仅能证明两次观察一致，不能声称获得不可变快照。此处记录的是受测的检测和失败语义，并非“所有并发都不会覆盖”的保证。

断线会使旧操作失效。旧复制/分叉的 finally 只能收尾自己的 intent，不能清掉新代次操作的状态或取消入口；旧分区读取不能清除较新冲突通知。排队事务与完成后的镜像更新均检查代次，迟到结果不成为新代次成功状态。

## 复现入口

```sh
cd /path/to/codex/workbench
npm run check
npm run desktop:chat
npm run desktop:copy:smoke -- /absolute/private/output
npm run concurrency:core:check -- --result /absolute/result.json
```

普通 check 只运行离线测试；最后一项显式启动隔离原生核心，使用生成的合成记录和网络拒绝策略。
